# 测试与交付经验

## 测试结论要带层级

| 层级 | 可以证明 | 不能证明 |
|---|---|---|
| 单元测试 | 路径、配对、ID、存储、消息验证等逻辑 | 实际窗口正常、C4D 能导入 |
| 浏览器测试 | 页面状态、快捷键契约、布局和桥接请求 | Windows 剪贴板或 OLE 已执行 |
| 发布 EXE 的 WebView2 测试 | 真宿主、图片解码、桥接与页面配合 | 注入事件等于物理跨窗拖放 |
| 用户实机确认 | 用户实际执行的对应操作 | 没执行的重复次数、贴图或其他环境兼容 |
| 真实升级测试 | 旧到新的一整次安装和数据保留 | 连续多次升级、自动回滚均可靠 |

CI 绿、PR 可合并、程序已装、用户喜欢、正式发布也是不同结论。失败和未验证项保留，不用“整体通过”覆盖它们。

## 先让测试抓住用户的问题

排版回归先复现“竖图被放进4:3框”和“大库右边空白”，再修代码，最后看到同一测试变绿。只测“页面没有崩溃”抓不住具体视觉问题。

导入测试覆盖重复、追加、父子重叠、同名不同路径、离线根目录和原封面优先。封面测试覆盖按钮、Ctrl+V、输入框文本粘贴、非图片拒绝、独立进程重启恢复，以及搜回已设封面的素材。

## 数据安全要说清比较了什么

对少量授权样本可比较文件内容 SHA256；大模型库可以记录大小/修改时间，但必须明确这不等于完整内容哈希。程序自有索引、映射和封面缓存的哈希适合检查只读试验有没有意外写入。

“1,034条记录”不等于“1,034张不同图片”。2026-10-19 的试用库包含 11 条已有模型封面、929 条项目参考图、94 条无预览；共享参考可以重复。此数字用于解释覆盖率，不是图像识别准确率成绩。

## 截图与交互证据

实际 EXE 截图必须来自实际 Windows WebView2，校验 PNG 内的像素尺寸。图片需要已解码；截图不能用网页模拟图冒充，也不能把“文件名写1920”当成尺寸检查。

公开证据使用合成资源。真实客户图片、模型名、完整路径、财务信息和含凭据日志留在本机，不因“需要证明测试”上传公开仓库。文字说明测试规模和结果即可。

资源管理器定位可先验证宿主解析了正确素材 ID，但如果测试替身没有真的启动 Explorer，应写“定位桥接验证”，不能说已经目视确认资源管理器选中。

## 交付前的最小检查

1. 发布目录中的 EXE 真正启动，不白屏，版本路径正确。
2. 导入/重扫、搜索、封面、定位，以及本轮触及的交互通过对应检查。
3. 关闭重开后索引、封面和配置保留；原资料不被改动。
4. 窗口大小、深浅主题、滚动、选中和缺图提示可用。
5. 拖拽或更新被修改时，另做对应真实链路测试，不用旧截图替代。
6. 只生成必要的一份可运行产物，保留回退点，说明可用/未完成，交给用户体验后暂停。

维护记录应列准确命令、提交、测试环境和计数。仅文档归档不重跑无关构建，更不借归档安装新客户端。
