# 产品目标与决策经验

## 以实际工作闭环判断进展

软件的核心不是“有漂亮界面”，而是让用户找到可复用模型并投入工作：选素材目录，只读收录，看到能辨认的图片，通过文字或截图找到目标，定位或拖入 C4D。用户是否愿意实际工作使用是最终产品判断；技术测试负责减少试用时的故障，不能替用户宣布满意。

进度应按一个个可操作闭环交付，而不是按写了多少代码、增加多少按钮或开了多少 PR 计算。每轮解决一个真实阻碍，例如“封面设完重启不丢”，不要同时重建客户端、数据库和更新器。

## 已确认的取舍

| 问题 | 当前决定 | 不要误读为 |
|---|---|---|
| 主展示 | 默认浅色，可切深色；完整原图瀑布流 | 任意移动的无限画布 |
| 主记录 | 一份模型文件一条记录 | 一个客户项目只能一条 |
| 文件夹 | 保留真实目录导航，多次导入追加 | 导入即移动或复制原资料 |
| 分类 | 真目录与虚拟分类是两回事 | 分类必须改磁盘目录 |
| Ctrl+V | 选中素材设置封面；输入框照常粘贴 | 全局抢走文字粘贴 |
| 以图搜图 | 专门入口，基础图片相似度 | 理解所有模型内容的语义 AI |
| 更新 | 用户点一次，下载校验、安装、重启、保留数据 | 显示新版本号就算升级成功 |

虚拟分类的产品意图不代表 V2 真实分类编辑已全部实现，状态见[当前状态](08-current-state-and-next-steps.md)。早期 Ctrl+V 搜索的讨论已经被后续“封面与独立搜图按钮”决定收敛，不能机械照搬旧快捷键方案。

## 不扩大成另一个软件

RenderCommander 属于项目工作台，包含项目浏览、状态、计时和经营管理。素材库只借鉴有用的读取和呈现方法，不引入报价、财务、排期、日报、复杂评分或同步系统。另一个素材整理器的任务也不混入本项目。

共享贴图、自动渲染、语义搜索、盘符重关联等可以记录为候选，但“提到过”不等于“已授权立刻开发”。涉及改原文件、批量删除或上传素材时必须单独确认。

## 已发生的验收教训

- v0.1.5 的白天/夜晚切换主要是升级标记。用户亲自从旧客户端升级，确认新功能、两条记录和原有封面都保留。这是已发布且人工验收的历史，不应被回退为未发布实验。
- 用户抱怨长期只有演示或禁用按钮，说明交付不能停在界面骨架。能力未接入就说未接入，接入后应直接给可运行 EXE。
- 用户不喜欢巨大的少量卡片，也不喜欢固定画框中的留白。不要把“填满窗口”理解成把一两张素材无限拉大。
- 用户最新明确保留瀑布流。分析别的软件只是提供借鉴，不构成换风格或换平台的批准。

## 继续讨论需求时

先复述实际问题和能看到的完成结果。关键偏好不清时给少量具体选项；已经回答的选择写进状态页，不反复问。阶段交付后暂停等待视觉确认，而不是无期限审查和打包。
