这份手册整理已经发生的需求变化、实现取舍、失败教训和验收方法，让后续协作不再从聊天记录重新猜需求。它是经验索引，不是安装器，也不会触发更新。

截至 2026-10-19，正式更新清单是 v0.1.7；V2 已有本机试用成果，但最新功能尚未全部合入 `v2-dev`。先读[当前状态](08-current-state-and-next-steps.md)，再决定从哪个提交继续。不能因为看见新界面就宣称正式更新通道已经升级到 V2。

## 几条不能再丢的结论

- 用户更喜欢完整原图、自然高低的瀑布流，不是统一裁切网格，也不是 PureRef 无限画布。
- 一份模型文件对应一条记录。同名不同路径不能凭名字合并；重复扫描同一路径不能重复收录。
- 普通 Ctrl+V 设置选中素材封面；专用按钮触发基础以图搜图。输入框内保留正常文本粘贴。
- 手动封面优先；项目参考图必须明确标记，不能冒充每个模型的专属渲染图。
- 原素材只读，封面和配置保存在程序版本目录之外；升级不能抹掉旧数据。
- 本机可启动、测试通过、用户确认、PR 合并、正式发布是不同状态，必须分别记录。
- 当前不换框架、不重做客户端、不把另一个项目管理工具整体搬进来。

## 归档规则

1. 每条经验说明“遇到什么问题、采取什么做法、如何验证、还有什么限制”。
2. 实现事实附提交或测试文档；用户反馈明确写成用户确认；未实施建议保持待办。
3. 只提交脱敏文字与程序代码。模型、贴图、商业图、真实截图、索引、缓存、个人配置、认证令牌及完整聊天记录不上传。
4. 未来更新先修改对应分类和状态页，不反复复制整份手册。稳定协议发生变化时另行审核，不能靠经验文档偷偷发版。
