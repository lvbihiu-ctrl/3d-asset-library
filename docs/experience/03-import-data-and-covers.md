# 素材导入与数据安全经验

## 三类文件分开

原始模型、贴图和渲染图只读；索引、封面映射和缓存保存在独立数据目录；EXE 和依赖放版本化程序目录。升级换程序，不搬原素材，也不把数据绑在某个旧 EXE 文件夹中。

程序可以备份自己的数据，但不能为“收录”复制整个模型包或 tex。对原资料的任何重命名、移动、删除、改引用，必须作为另一个经批准的操作。

## 多根目录与重复扫描

已实现的去重依据是归一化完整路径的 SHA256 ID。重复导入相同目录、父子目录交叠，不重复生成模型记录；同名不同路径保留两条。这不是内容哈希去重，也不能宣称识别了跨目录的相同模型。

多次选择文件夹是追加而非清空原库。记录保留来源根目录/成员关系，重扫只处理已保存且可用的根目录；移动盘断开时保留索引并提示，不静默删除。盘符变化自动重关联、跨设备稳定 ID 仍需专门设计，不能从路径去重推导出来。

旧单根目录索引要兼容读取。写入新增多根元数据前备份；回退程序时还要考虑旧程序能否理解新数据，不能只说“旧 EXE 还在就万事大吉”。

## 封面不是任意一张附近图片

现有扫描器优先模型同名图片及明确的 preview/cover/thumb/render 等后缀，单模型目录才允许更宽松的目录名或通用封面匹配。纹理和参考图不能仅因离模型近就充当专属效果图。

保留三种不同身份：

| 来源 | 意义 | 规则 |
|---|---|---|
| 人工指定封面 | 用户确认用它辨认该素材 | 最高优先，不被重扫替换 |
| 可靠模型配图 | 按明确文件名规则匹配 | 已有可用关联继续保留 |
| 项目参考图 | 同项目共享的参考，不等于模型渲染 | 单独字段与标记，不覆盖专属封面 |

项目参考图只在所选根目录内查找明确的封面/预览目录和合适候选。几百条记录引用同一张项目图，并不等于几百张不同模型预览；不得用这个数量宣传识别准确率。

## 手动封面持久化

Ctrl+V 或按钮从系统剪贴板读取图片，缓存到软件自己的目录，原子更新封面映射和保存索引。重启、重扫、多文件夹追加后都要仍然关联原记录。输入框正常粘贴文本；非图片剪贴板要明确失败，不能空写封面。

封面 URL 更新需要可验证的修订标记，防止同一路径新图片被浏览器旧缓存挡住；本地保存成功后还要检查界面实际解码出新图。

## 以图搜图的真实边界

当前使用 9×8 dHash 和汉明距离，比较封面图像特征；不是对 C4D 几何、语义或材质的理解。项目共享图会产生相同/近似分数。相同图 Top-1 成功不能外推成任意截图、裁切、跨视角或语义搜索都可靠。

## 系统缩略图的候选试验

Windows 可以通过系统缩略图接口提供某些文件的预览。这不是重新渲染模型，是否有效取决于文件和本机支持；缺预览时可能只有通用图标。此能力尚未接入当前素材库，不把 RenderCommander 的调用代码当作成功率证据。

若后续批准试验：少量只读模型、独立缓存、强制区分缩略图与图标、失败明确显示缺图，始终保留人工封面优先。不照搬会写入原项目封面、从 Textures 随机取首图、无根目录限制或长期旧图缓存的实现。
