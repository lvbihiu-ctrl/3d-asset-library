## 2. 新确认的产品需求

### 2.1 最终渲染图优先，而不是 C4D 视口缩略图

- 用户明确指出：Windows 文件管理器/C4D 显示的 `.c4d` 缩略图 **不是最终商业渲染效果**。
- 因此素材墙封面优先级应为：
  1. 用户手动 Ctrl+V 指定的最终渲染图（最高优先级）；
  2. 已可靠匹配的项目成品渲染图（候选要可确认，勿将贴图/参考图自动当成成品）；
  3. C4D 自带预览（如能提取，必须标注为“场景预览”，不能冒充成品图）；
  4. 暂无预览。
- 对既没有成品图也没有可用图片的场景，用户接受**必要时主动渲染一次**，但**不允许每次浏览都重新渲染**。大批量自动打开 C4D/Redshift/Octane 渲染不属于当前阶段任务。
- 生成缩略图是一次性/按需缓存流程；原模型、贴图和项目目录保持只读。

### 2.2 Ctrl+V 有两种用途，必须避免快捷键冲突

**现有功能：** Ctrl+V 粘贴图片，执行以图搜图。

**新增功能：** 选中一个素材条目后，把剪贴板图片设为该条目封面。

- 不要因为存在“已选中卡片”就静默把所有 Ctrl+V 改成“设置封面”，导致原有以图搜图失效。
- 设计明确、可感知的操作上下文：例如“设置封面”按钮使该卡片进入一次性粘贴封面模式，或在卡片详情的封面区域聚焦时粘贴；普通素材墙仍沿用 Ctrl+V 搜索。
- 用户希望**整个操作只需要复制图片 + 选中目标 + Ctrl+V**，不用每次弹出本地图片选择器。可以让用户测试具体交互后确定最省事方案。
- 封面覆盖时要能撤销/重新设置，不影响原始图片或场景。
- 用户以后可能更换盘符/移动硬盘路径；封面关联需要避免只依据临时序号或浏览器窗口。

### 2.3 C4D 素材包与 tex 目录

真实示例表明一个 C4D 工作项目常有：

- 一个或多个 `.c4d` 场景；
- `tex/` 文件夹中的 JPG/PNG、PSD、EXR/HDR、材质/ShaderLink 等；
- 可能在同一目录或其它目录里的最终渲染图。

素材墙**不应该把同一项目的每一张贴图都展示为独立“主素材”卡片**，导致几十个占位图。但也不能盲目把整个上层文件夹压成一条记录：**同一个目录中可能存在多个独立 C4D 场景**。

建议用“场景/素材条目为主体，相关资源和目录为分组信息”的最小实现。仅根据目录关系归组时，标注“同目录资源”，**不得假称已读取 C4D 的真实引用依赖**。

当前 PS1 扫描器 `Classify` 会把所有 `.exr` / `.hdr` 分类为 `HDRI`，这不准确（普通纹理、渲染输出也可能是 EXR）。`tex` 中的图片还被过滤出预览候选，未来需要更明确区分“纹理”和“成品图”。此项可在主闭环后做**局部**修正，切勿边改边扩张范围。

## 4. 预览来源技术判断（只做参考，不扩大本轮范围）

- Windows Shell 可尝试读系统已有缩略图，但该图**通常不代表最终渲染**；不是解决本次封面需求的首选。

## 8. 2026-10-17 追加：C4D 官方 MCP 模板实验（与素材库主线分开，不要求马上实装）

用户进一步明确：**现阶段只做低成本验证，不开发完整的自动化素材管理系统。** 目标是将已调好的 C4D + Redshift 灯光/相机/背景作为模板，换入另一套产品模型后复用场景设置与 RS 灯光链接（包含/排除），避免每换一套模型都重新搭场景。希望无需执行“保存项目并包含资源”，尽可能沿用原始资源路径；若原路径失效，应报告缺失，不擅自复制/修复。

### A/B 两种模型输入共用同一份模板

- **A — 已分部件的规范模型（首轮实际测试）**：已有主体、金属、玻璃、镜头、支架等独立对象。通过 MCP/本地 C4D API 读取当前选择的对象层级，建议或自动匹配到模板槽位；用户确认后在**测试场景副本**中建立标准分组关系。优先最小化改动。
- **B — 外部杂乱模型（第二轮实验）**：名称混乱、嵌套层级、材料和对象混合、部分网格已合并。先生成只读对象清单和分类建议，标示置信度/需要人工确认项，再由用户确认分类。不能凭材质或名称保证语义，不能承诺自动把合并网格精确拆成独立零件。不要静默重命名/覆盖源模型。
- 两条路线输出同样的“功能槽位映射”，但原始对象可以保留原名和原层级。允许“未归类”，不要求所有产品具有完全相同的部件。

### 建议最小模板结构

```text
STUDIO_TEMPLATE
  00_PRODUCT_SLOTS
    BODY
    METAL
    GLASS
    OPTIONAL_PARTS
  01_RS_LIGHTS
    KEY
    FILL
    RIM
    METAL_STRIP
  02_STAGE
    CAMERA
    BACKGROUND
    FLOOR
```

注意：以上是建议的**功能分组/映射**，不是必须克隆/迁移每个 C4D 物体节点；实际绑定可能使用 Null 分组、对象列表和光源链接。某些对象同时属于多个类别，应允许多对一/一对多映射或人工指定例外。材质名称不等于几何部件类型。

### 最有价值的首轮测试：灯光关系继承

1. 在用户安装的最新 C4D 中，使用**不涉密测试文件和副本**，创建 2 个已分开的零件（BODY、METAL）、两盏 RS 灯。不要先写大型插件。
2. 在 RS 灯光的 Project/Light Linking 设置中，将 METAL 分组作为 Include/Exclude 目标，并启用相应 **Apply to Children**（影响子级）。Redshift 官方说明明确存在这项机制：
   - https://help.maxon.net/c4d/2025/de-de/Content/_REDSHIFT_/html/Light%2BAnd%2BShadow%2BLinking.html
   - https://help.maxon.net/r3d/cinema/en-us/Content/html/Redshift_C4D_Light.html
3. 将 METAL 子组内的旧模型移除、换入新模型（**仅在测试副本中**），保持灯光关联到固定分组容器；验证新对象是否继承正确的照明和阴影链接。要实机测试，不能仅凭官方功能描述就假定一定生效。
4. 检查 C4D 原生 **Replace with** 命令是否比自行开发替换逻辑更合适：
   - https://help.maxon.net/c4d/en-us/Content/html/68788.html
5. 做一张小尺寸验证渲染，比较替换前后灯光链接行为。**不要声称灯光引用保留即等于高光、阴影效果完全一致**；尺寸/曲率差异仍可能需要调灯。

### MCP 的作用与边界

- 首轮仅测试读取当前选择对象、列出层级、记录来源路径、按预设槽位建议映射。成功后测试移动/挂接进固定模板分组。
- 优先使用官方 C4D MCP，查看它实际暴露哪些工具和权限；不能调用的操作再评估 C4D Python API。外部模型的独立网格自动拆分不作为首轮目标。
- 读取源场景可以只读；**不要修改真实客户/外部原文件**。测试更改只在用户明确认可的临时副本中实施，做好撤销/回滚。原始贴图只引用，不因整理执行“保存项目并包含资源”。
- **目前用户仍在安装最新版本 C4D，MCP 尚未连通，所有场景自动化能力未在用户机器测试。** 先确认版本、权限和基础连接，再做一个 A 类型模型的可重复实验。完成 A 后再处理 B。

这项模板实验属于 C4D 资产复用的独立小测试，**不取代前文 V14 的 Ctrl+V 成品封面主线**，也不应合并成大型重构。


## 9. 未来候选：共享贴图库与极简收录（只记录，不占用当前 M1–M4 工期）

用户在实际素材工作中遇到多个 C4D 场景的 `tex` 文件夹含有大量重复贴图，希望**相同贴图只需存一份、多个场景共用引用**，同时希望导入素材时尽可能“丢进去即收录”，不需要严格命名、人工分类或复杂步骤。

- **现在先考虑只读去重检测，不改变现有素材**：用大小预筛、文件内容 SHA-256 确认相同（包括不同名同内容）；同名不同内容严格分开。相似图/不同分辨率、UDIM 序列、EXR、多通道图、颜色空间/不同用途等不要自动互相代替。
- **长远目标是“一个共享贴图库 + 多个场景引用”**，但索引发现重复 ≠ 真正释放磁盘空间；真正去重需要 C4D/Redshift/Octane 中的纹理引用改为可信的统一路径，并对场景副本渲染验证后才允许删除重复实体。绝不直接批量删除 `tex` 或自动修改原客户文件。
- 可先评估 Maxon 原生「Files > Texture Paths / 额外搜索路径」与「Project Asset Inspector > Relink Assets」，特别注意绝对路径会覆盖搜索路径、节点材质对搜索路径的递归限制。官方文档：https://help.maxon.net/c4d/en-us/Content/html/68600.html 和 https://help.maxon.net/c4d/s26/en-us/Content/html/PREFSFILES-PREF_FILE_MAIN_GROUP.html
- **用户目标交互**：拖入/选择模型或目录 → 自动扫描及预览匹配 → 后台发现重复贴图并复用已知索引 → 只有冲突/不确定项才弹出确认 → 完成收录。无需强制重命名。真正改变引用时另设有备份、变更预览和验证的一键操作。
- **当前优先级仍是 V14 主线：双击启动 → 扫描真实模型 → Ctrl+V 设置封面并持久化 → 以图搜图 → 定位原文件。** 本条不应触发立刻新增开发、数据库迁移或复杂重构。
