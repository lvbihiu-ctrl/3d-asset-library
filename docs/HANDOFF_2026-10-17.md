5. 新封面必须能被**现有的 Ctrl+V 以图搜图**使用，找到对应条目并定位原始 `.c4d` 文件。不要降低原有搜索效果。

先完成并在用户机器上验证这条闭环，不开展其它重构。

## 2. 新确认的产品需求

### 2.1 最终渲染图优先，而不是 C4D 视口缩略图

- 用户明确指出：Windows 文件管理器/C4D 显示的 `.c4d` 缩略图 **不是最终商业渲染效果**。
- 因此素材墙封面优先级应为：
  1. 用户手动 Ctrl+V 指定的最终渲染图（最高优先级）；
  2. 已可靠匹配的项目成品渲染图（候选要可确认，勿将贴图/参考图自动当成成品）；
  3. C4D 自带预览（如能提取，必须标注为“场景预览”，不能冒充成品图）；
  4. 暂无预览。
- 对既没有成品图也没有可用图片的场景，用户接受**必要时主动渲染一次**，但**不允许每次浏览都重新渲染**。大批量自动打开 C4D/Redshift/Octane 渲染不属于当前阶段任务。
- 生成缩略图是一次性/按需缓存流程；原模型、贴图和项目目录保持只读。

### 2.2 Ctrl+V 有两种用途，必须避免快捷键冲突

**现有功能：** Ctrl+V 粘贴图片，执行以图搜图。

**新增功能：** 选中一个素材条目后，把剪贴板图片设为该条目封面。

- 不要因为存在“已选中卡片”就静默把所有 Ctrl+V 改成“设置封面”，导致原有以图搜图失效。
- 设计明确、可感知的操作上下文：例如“设置封面”按钮使该卡片进入一次性粘贴封面模式，或在卡片详情的封面区域聚焦时粘贴；普通素材墙仍沿用 Ctrl+V 搜索。
- 用户希望**整个操作只需要复制图片 + 选中目标 + Ctrl+V**，不用每次弹出本地图片选择器。可以让用户测试具体交互后确定最省事方案。
- 封面覆盖时要能撤销/重新设置，不影响原始图片或场景。
- 用户以后可能更换盘符/移动硬盘路径；封面关联需要避免只依据临时序号或浏览器窗口。

### 2.3 C4D 素材包与 tex 目录

真实示例表明一个 C4D 工作项目常有：

- 一个或多个 `.c4d` 场景；
- `tex/` 文件夹中的 JPG/PNG、PSD、EXR/HDR、材质/ShaderLink 等；
- 可能在同一目录或其它目录里的最终渲染图。

素材墙**不应该把同一项目的每一张贴图都展示为独立“主素材”卡片**，导致几十个占位图。但也不能盲目把整个上层文件夹压成一条记录：**同一个目录中可能存在多个独立 C4D 场景**。

建议用“场景/素材条目为主体，相关资源和目录为分组信息”的最小实现。仅根据目录关系归组时，标注“同目录资源”，**不得假称已读取 C4D 的真实引用依赖**。

当前 PS1 扫描器 `Classify` 会把所有 `.exr` / `.hdr` 分类为 `HDRI`，这不准确（普通纹理、渲染输出也可能是 EXR）。`tex` 中的图片还被过滤出预览候选，未来需要更明确区分“纹理”和“成品图”。此项可在主闭环后做**局部**修正，切勿边改边扩张范围。

## 3. 已见到的真实测试结果（非自动化验收）

- 在 Windows 上手动从命令行运行 `tools/扫描并打开.ps1`，成功弹出文件夹选择器。
- 通过修复启动器后，用户截图显示素材墙**能够打开**并扫描到约 **15 个文件条目**，包含 C4D、HDR/EXR 和其他资源；但**页面上没有显示所需的产品成品预览图**。
- 因此“扫描到文件”与“能用图识别模型”是两个不同验收点。**目前不可宣布真实项目预览与以图搜图闭环已经通过。**
- 启动器第一次出现过闪退/中文路径乱码。对 Windows `.cmd` 文件应特别注意 **ASCII 兼容命令、CRLF 换行**、PowerShell 中文脚本路径以及有错时停留显示报错。
- **GitHub `main` 仍有旧的 `01_双击_选择素材文件夹.cmd` 内容**（使用 `chcp 65001` 和含中文 `-File` 路径）。聊天里给过临时 v2 启动器，但**没有提交到正式仓库，也没有完整 Windows 实测结论**。不要把“聊天里发过修复版”当作“仓库已修复”。
- 用户获得过几个独立 HTML 小原型（分组、手动设置封面、Ctrl+V 设置封面），但它们**没有合并入本仓库的 V14**，并非正式项目功能；也**没有完成用户电脑上的端到端验收**。继续开发时不要基于那些原型另起炉灶，优先改 `app/素材工作台.html` 和必要的 PS1 部分。

## 4. 预览来源技术判断（只做参考，不扩大本轮范围）

- Windows Shell 可尝试读系统已有缩略图，但该图**通常不代表最终渲染**；不是解决本次封面需求的首选。
- C4D 文件可能有内嵌 JPEG 预览，需针对版本实测；不能保证都存在。
- EXR/HDR 转 JPG 可参考 Apache-2.0 的 OpenImageIO；是否需要外部可执行文件及部署成本须提前评估，不应本轮擅自安装大型依赖。
- GitHub 项目 SageThumbs 2K 含提取 C4D 预览的参考实现，但其 PolyForm Noncommercial 许可不适合不经评估直接复制到商业使用场景中。
- **本轮最值得先做的是用户手动指定最终渲染封面并形成持久缓存**，不要求解决所有原生格式解码。
