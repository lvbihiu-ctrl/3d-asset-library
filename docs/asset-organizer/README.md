# 3D 素材整理器｜项目需求基线（Grill-me 1～8 轮）

**文档日期：2026-10-18　｜　状态：需求访谈进行中，尚未立项开发**

## 1. 项目定位

这是一项**独立于「3D 素材管理器 V2」的工具需求**，但预期为后者准备素材。

- **素材整理器**：负责收集、发现、分析、分组、检查、归档和提交可供管理器使用的素材记录。
- **素材管理器 V2**：负责显示、搜索、筛选、预览和调用素材，包括后续的 C4D 工作流。
- 两个工具的**仓库边界、数据协议、是否共享数据库、独立进程还是模块**均未讨论完成，暂不擅自确定。
- 此路径中的文件只用于记录整理器需求，**不构成原管理器 V2 的新功能任务，也不授权修改其代码**。

## 2. 用户要解决的问题（第一轮）

素材散落于硬盘与下载目录；下载包（ZIP/RAR/7z 等）结构不一致；许多模型缺少可视封面；模型、贴图、不同格式及旧工程之间关系混乱。目标是**低人工干预地收集、整理、入库，让素材之后能直观看到并快速调用**。

### 目标工作流（原则已认可，具体设计未定）

1. **入口**：手动拖入模型/文件夹/压缩包，或者可选监控指定下载目录。
2. **识别**：分析文件结构、模型和贴图关系、已有预览图、可能的重复项；优先本地规则。
3. **分流**：旧有素材优先索引，不移动；新下载素材保留原始包关联并归档。
4. **待确认区**：只请用户批量确认模型关系、封面归属、重复或其他疑难项。
5. **先可用**：可以索引并搜索后先入库；缺少封面的素材进入后台预览任务队列。
6. **对接 V2**：入库结果供现有素材管理器展示和搜索；**具体数据接口未决**。

该流程是需求方向，不代表已经有可运行实现。

## 3. 已确认决策（Grill-me）

| 轮次 | 用户选择 | 已确认范围 |
|---|---|---|
| 1 | E：以上全有 | 目标涵盖压缩包、旧素材、缺封面、模型贴图关系与自动收集 |
| 2 | D：两种模式 | **旧素材虚拟整理，不移动原文件；新下载素材自动归档** |
| 3 | B：自动整理 + 疑难确认 | 能可靠识别的自动处理；不确定的集中待用户批量确认 |
| 4 | D：手动拖入 + 可选自动监控 | 优先拖入；监控是可开关功能；浏览器一键收集不是当前已选项 |
| 5 | B：完整素材包 + 虚拟多分类 | 硬盘保持素材包内部模型/贴图结构；软件中可多标签、多分类和修改展示名称 |
| 6 | B：本地优先，AI 按需 | 常规识别无 AI 也能工作；疑难才可选 AI；具体成本/云端策略未定 |
| 7 | B：先入库，后台补封面 | 已有可靠封面优先；缺封面的模型可先被搜索；后台按适配能力补图 |

## 4. 核心原则及风险

- 原素材包与工程之间的贴图、插件、相对路径关系不能因为「分类」被随意改写。
- 一个素材可在管理器中归属多种用途/标签，不为每个标签复制一份物理文件。
- **素材展示名称**可以优化，而不是必须重命名磁盘文件。
- 封面须对应真实模型：已有原始效果图、程序生成几何预览、无预览图，应明确区分。不得让生成式 AI 想象图片后冒充模型真实封面。
- C4D/RS/OC 等工程可能受版本、插件、材质和外部纹理限制；「自动完整渲染所有 C4D 文件」不属于已确认承诺。
- 压缩包异常、超大任务、断电、重复文件、空间不足需要特别设计；**具体决策尚未全部锁定**。
- 实际归档规则应先经过少量真实授权样本验证；没有用户确认前不把物理删除、移动和去重权限假设为已获授权。
