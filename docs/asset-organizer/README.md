# 3D 素材整理器｜已废弃方案归档

> **状态：已停止／不再推进（2026-10-19，用户明确决定）**
>
> 本文档为历史研究记录，不是当前开发任务。独立「3D 素材整理器」v0.1/v0.2 的扫描器与规则式虚拟分类路线停止迭代；不再按本方案开发独立整理器、批量 C4D 自动预览或 AI 自动分类。**现有「3D 素材管理器 V2」继续独立推进，不受本决定影响。**
>
> **不要据此创建 Issue、自动派发 Codex、执行归档或修改 V2。** 未经用户再次明确授权，不恢复本方案。

## 1. 为什么废弃

用户在 Windows 上实际运行独立试用版 v0.2，并提供了「自动整理结果」截图。该批次的页面统计显示：

| 指标 | 页面显示 | 含义 / 局限 |
|---|---:|---|
| 发现模型 | 238 | 找到了文件，不等于理解模型 |
| 名称／目录规则归类 | 125 | **未验证**分类准确率 |
| 待识别 | 113 | 仍需更多信息 |
| 封面匹配候选 | 10 | 只是候选，不等于 10 张正确封面 |
| 自动识别 C4D 真正的模型外观 | 未实现 | 关键价值缺失 |
| 直接得到可用、可辨认的素材库 | 未达到 | 无法明显替代人工整理 |

v0.1/v0.2 的展示主要依赖文件名、文件夹和占位图。将扫描结果排列成卡片不等于把素材整理成可直观辨认和调用的库。继续叠加批量 C4D 打开、生成几何预览、RS/OC 依赖适配和 AI 分类，成本与成功率仍无验证，不应继续投入到此独立路线。

**结论是本路线不值得继续投入，**并非断言全部自动整理技术永远不可行，也不代表 V2 应停止开发。

## 2. 曾经确认的需求（仅历史记录）

- 旧素材虚拟整理、不移动原件；新素材保留整包结构安全归档。
- 能确认的自动处理，不能确认的集中提示；手动拖入和可选下载目录监控。
- 本地优先、AI 可选；先收录可查询，再考虑后台封面。
- 第八轮主方案 **B：安全优先 + 智能去重**。
- 8.1 **B：压缩包 + 完整内容双层校验**；只有完整等价才考虑跳过新副本。
- 8.2 **B：安全归档 + 批量确认清理**；绝不自动删除下载原件。
- 第九轮方向 **B：整理器独立运行，V2 统一操作界面**；**9.1 数据所有权／入库协议未确认**。
- **8.3 断电恢复／磁盘空间／临时文件清理未确认**。
- C4D **完整工程收录（A）**；每个 C4D 一张卡、同目录归组（B）。
- 明确的备份目录默认跳过扫描和建卡（A），**过滤不等于删除**。
- 公共贴图库登记、按需检查（B）；缺失贴图自动寻找候选、**不修改工程（B）**。
- 贴图候选的分级匹配方案未获用户最终确认；不得记为已定要求。

这些历史选择随项目一并归档，不构成当前已批准的开发规格或新的数据删除授权。完整过程见 [GRILL_LOG.md](GRILL_LOG.md) 和 [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md)。

- 仅当以后存在经过真实工程验证的低成本方案，并且用户明确重新批准时，才重新评估素材整理自动化。
