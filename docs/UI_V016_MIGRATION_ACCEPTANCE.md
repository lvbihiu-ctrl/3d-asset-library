# v0.1.6 素材墙升级 · 实施 / 迁移 / 回滚 / 验收方案

> 状态：设计决策已确认，Windows 实机验收未开始。本文不构成“已发布 v0.1.6”的声明。
>
> 2026-10-18 用户选择：**视觉参考 PureRef、自动排版瀑布流、虚拟分类＋真实文件夹、快速找素材、默认浅色**。提供的 15 张图片**只作设计参考**，不自动导入正式版。
>
> 阅读顺序：`AGENTS.md` → 本方案 → `GLOSSARY.md` → 当前 `app-v0.1.5.ps1` / `launcher/Program.cs`。

## 1. 真正要解决的问题

现有 Windows EXE v0.1.5 已验证一键更新、显示两条真实模型卡片、保存封面，以及文件拖拽（Shift 拖入合并当前 C4D 工程）。但 UI 是固定尺寸 WinForms 卡片和顶部工具栏，缺少易浏览的瀑布流、虚拟分类和真实文件夹的双轨导航。用户优先改善 **日常找模型的可读性**，而不是新增无限画布、复杂标签系统或上传客户作品。

### 目标体验
- 默认浅色；支持原有夜间模式。素材封面是主视觉，宽高随实际预览比例适度变化，以自动多列布局展示；不承诺真正无限画布、自由拖动或缩放。
- **快速找素材**一直是默认工作流；搜索、导入文件夹、粘贴封面、以图搜图、全部素材、定位和检查更新必须看得见、点得动。
- 双轨侧栏：虚拟分类（不动原始文件）＋真实文件夹导航（目录只读）。
- 模型条目仍对应真实模型路径；一条模型不会因为出现在多种浏览入口就复制实际文件。
- 素材详情可以看到名称、类型、相对路径、完整路径、分类和封面来源；路径无效/硬盘断开时正确提示。

### 明确不做
- 不把 15 张设计图片提交 GitHub 或自动塞进真实资产库；不生成假模型文件/假 MB/假收藏数。
- 不做无边界自由画布、复杂自动标签、识别模型内部几何/材质、自动迁移项目、云端同步。
- 不上传真实客户素材、封面、缓存、贴图、模型；不改变其所在磁盘的文件结构。

## 2. 当前已证实的技术基线（避免误判）

- 稳定版本 `desktop-updates/native/latest.json` = **0.1.5**，锁定不可变 SHA256 和 GitHub 固定 commit 的 PS1 脚本 URL。
- `desktop-updates/native/app-v0.1.5.ps1`：WinForms GUI + 扫描 + 预览 + dHash 相似搜索 + Ctrl+V 设置封面 + C4D 原生 FileDrop + 检查更新代码。
- `desktop-updates/native/launcher/Program.cs`：固定 EXE 启动器，校验 `.runtime/override.ps1` 和 SHA256，优先运行覆盖脚本。
- 已有数据：`D:\Codex\3D-Asset-Library-Ready\.local-data\catalog.json` / `covers.json` / `covers\` / `thumbs\`；安装配置与主题在 `D:\Codex\3D-Asset-Library-EXE\`。
- 素材 ID 目前以 **完整文件路径的 SHA256** 生成；**路径/盘符改变后并不保证 ID 保持不变**，分类和封面映射不可虚称会自动恢复。
- `app-v0.1.5.ps1` 的扫描逻辑还会收录一部分独立图片、HDR/EXR、SBSAR 条目；不应在 UI 升级中静默更改收录类型。
- 官方 `frontend-design` Skill 已存在 `.agents/skills/frontend-design/`；视觉设计可参考，但它不能把 WinForms 自动变成 HTML。
- 需要先验证“纯 WinForms 布局是否达到视觉要求”。若改用 WebView2/浏览器 UI，必须另行验证 Windows 原生拖拽、Shift/C4D、封面剪贴板与是否需要更换启动器。**架构迁移尚未批准**。

## 3. 安全迁移路径（先保证旧版能用）

### S0 · 冻结基线与写入方案（本次）
1. 从 main 新建 `codex/v016-ui-migration-preview`，只在分支开发，不直接发布。
2. 保存最新正式 `main` commit、`latest.json` 原内容、稳定脚本 SHA；不得修改正式 manifest。
3. 建立术语表、本方案以及测试检查表。
4. Windows 启动任何候选版前，由本地 Codex **读取并备份**上述 `.local-data` 和 `settings.json`、`.runtime`；记下文件校验值/备份目录。
5. 候选源码使用**新文件名**，不覆盖已发布的 v0.1.5 脚本。

### S1 · 安全的布局候选（首个开发里程碑）
- 在独立分支新增 v0.1.6 **预览脚本**，优先复用旧扫描、封面、剪贴板、dHash、原生拖拽和更新函数，而不是复制一套不可兼容的新模型数据库。
- 新的窗口结构：固定顶栏（原有核心操作）＋左侧双轨导航＋中央自动瀑布流卡片＋可选右侧详情。
- 若 WinForms 无法在可接受成本内达到原 HTML 样机的视觉要求，**停止在 WinForms 上扩功能**；提交技术验证结论，再提出 WebView2 方案，不得直接切正式 EXE。
- 未运行在用户 Windows C4D 上之前，称为 **候选实现/未验证**，不是“做完了”。

### S2 · 双轨分类（独立、本地、可撤销）
- 新建**独立**的分类映射文件 `D:\Codex\3D-Asset-Library-Ready\.local-data\ui-categories.v1.json`，只记录条目 ID → 虚拟分类；分类表和浏览状态也存于该文件或单独本地设置。**不修改** `catalog.json` / `covers.json` 结构。
- 首次没有分类文件时显示“未分类”，不可默认改写已有两条封面数据。失败时退回“全部素材＋原始文件夹”只读视图，不破坏模型可用性。
- 分类修改仅影响**虚拟分类**。真实文件夹模式只能筛选真实路径，不移动文件。
- 每次写入采用备份/临时文件/校验的安全策略；需要实验验证中途失败的回退行为。重扫时用现有 ID 重新关联；盘符变化/路径重命名场景须报告未匹配项，不静默猜测。

### S3 · 完整 Windows 实机验收（不可跳过）
在 `D:\Codex\` 下使用独立测试副本运行候选，不替换安装目录 EXE 或用户数据。先用**假数据/副本**验证行为，再用原有两个真实模型按只读方式核验，不能重写用户封面。
通过后用户确认界面布局及 C4D 操作。PR 保持 Draft，不直接合并、无正式自动更新。

### S4 · 正式一次性发布（只有 S3 全部通过后）
1. 冻结候选内容，Windows CI 检查 PowerShell 解析；本地实机再次测试启动和升级。
2. 创建不可变 commit，计算候选正式脚本的**实际字节 SHA256**（考虑 BOM/编码）。
3. 更新 `desktop-updates/native/latest.json`：0.1.6、固定 commit URL、正确 SHA；再次从远端验证 manifest 与脚本匹配。
4. 使用现有 EXE 内的“检查更新”升级，确认两条真实模型、原封面、原生拖拽等**全部还在**。只能在此时宣布 v0.1.6 发布。

## 4. 回滚设计（覆盖 UI、分类与更新三层）

- **最简单回退：** 候选只在独立分支／独立测试副本，停止候选并打开原始已安装的 `3D素材管理器.exe`，它继续使用 v0.1.5；**绝不在评估阶段改线上 latest.json**。
- **用户数据回退：** 原 `catalog.json`、`covers.json`、`covers\`、`thumbs\` 不迁移不删除。新增分类使用 sidecar 文件，不修改旧格式。要恢复旧体验，只需不读取新分类映射；数据仍可保留备用。
- **已正式 OTA 后启动失败：** 更新器现有 `.runtime/override.backup.ps1` 和 `.runtime/override.backup.sha256` 可作候选回退点；恢复前先关闭进程、核对备份 SHA256，使用本机 Codex 生成的**可审计恢复工具**，不要让用户手工编辑脚本。注意：备份可能是上一次覆盖版，**不能假定它一定等于 v0.1.5**。
- **确定恢复到 v0.1.5：** 以已发布的固定 commit + SHA256 重新下载并校验已知可用 `app-v0.1.5.ps1`，再把核实过的脚本作为本地 override 放回。不要回写、重置或强推 GitHub 主分支；线上 manifest 回滚需要另外讨论。
- **先恢复软件，后恢复新增分类数据**；任何回滚都不能删除用户原始模型或历史封面。
- **发布前必须做一次启动失败的恢复演练**，不演练不发布。

## 5. 验收清单（逐项标注真实结果，不得事先宣称通过）

| 编号 | 验收动作 | 合格标准 |
|---|---|---|
| A01 | 双击原 EXE / 启动候选 | 稳定版仍正常运行；候选窗口能打开，不空白不闪退 |
| A02 | 打开旧目录/模型 | 原两条真实素材、两张封面仍出现，模型路径未变 |
| A03 | 从新卡片拖模型到 C4D | 普通拖动按原逻辑工作 |
| A04 | 按住 Shift 拖模型到 C4D | 在用户当前 C4D 场景合并，未仅打开新工程 |
| A05 | 顶部核心操作 | 导入、搜索、粘贴封面、以图搜图、全部素材、定位、更新入口可见 |
| A06 | Ctrl+V 粘贴封面 | 选中的模型卡片保存封面，关闭重开仍保留；普通以图搜图入口也正常 |
| A07 | dHash 图像检索 | 真实截图相似搜索能返回结果；不得夸大成 AI 视觉识别 |
| A08 | 虚拟分类 | 可以新增分类、归类、筛选；源文件未发生移动／修改 |
| A09 | 原始文件夹 | 路径层级正确，切换过滤不更改文件结构 |
| A10 | 分类持久化 | 退出重启、重新扫描仍保留匹配 ID 的分类；改盘符显示未匹配而非误归类 |
| A11 | 视觉布局 | 1100×600、1920×1080 展示无严重遮挡；瀑布流随窗宽变列，不遮住按钮 |
| A12 | 明暗主题 | 默认浅色，原夜间切换正常，选择按原偏好保存 |
| A13 | 故障保护 | 目录未接盘、坏分类 JSON、坏预览、剪贴板空、取消导入都不会破坏库 |
| A14 | 更新器 / 回滚 | 正式发布前测 SHA 拒绝错误脚本与恢复入口；线上 manifest 维持 0.1.5 直到批准 |
| A15 | 大目录压力测试 | 使用真实 100 / 1000 条时记录耗时、滚动和内存，测后再定性能结论 |
| A16 | 资源与安全 | 不把任何真实图、.c4d、贴图、缓存提交 GitHub；原始文件只读 |

> 本表目前 **全部未在 v0.1.6 候选上验证**。v0.1.5 的已通过项目只作为基线记录，不可替代新版本验收。

## 6. 交付关口 / 谁有权限做什么

- ChatGPT：方案整理、修改隔离分支、审查差异、CI 静态检查；**不能**宣称已触达用户 Windows 或 C4D。
- Windows Codex：本地保护备份、启动候选、收集错误、运行 C4D 拖拽/Shift 实测。
- 用户：选择最终视觉方案，做少量真正关键的人机验收，并决定是否公开更新。
- **Gate 1：** 提交新文档、候选脚本；不动 main、不发布。
- **Gate 2：** 代码审核 + Windows 静态验证 + 不涉密测试运行；失败即退回稳定版。
- **Gate 3：** 原始两条素材/封面、拖拽、检索、分类持久化均通过后，才允许发布 0.1.6。

## 7. 目前还没证实的事情（不能脑补）
- WinForms 能否达到用户看到的 HTML 样机精致程度与相同比例的图片墙。
- 候选版重新实现布局后，WinForms FileDrop 对所有子控件仍然生效。
- 缩略图绘制与 1000+ 模型的滚动是否够流畅。
- 本地分类 sidecar 在外接盘改盘符后的重连体验。
- Windows 现有升级器能否在发生严重 UI 故障时由用户无代码操作恢复。恢复工具需要实机演练。

## 8. 本次开发允许改动的边界

只允许在**独立分支**新增预览版脚本和相关静态测试，必要时修改本方案/GLOSSARY。未经 Windows 测试和用户批准，禁止修改正式：
`desktop-updates/native/latest.json`、`desktop-updates/native/app-v0.1.5.ps1`、`desktop-updates/native/launcher/*`、`.github/workflows/release-native-exe.yml`、`catalog.json`、`covers.json` 或任何用户模型／封面文件。
